# 托盘展开 · TrayBridge 1.0.2

面向 macOS 15 的轻量菜单栏工具。点击菜单栏里的展开图标，或按 **Control + Option + 空格**，在系统原生下拉菜单中选择被刘海挡住的菜单栏项目，打开它原有的菜单或面板。

纯 Swift / AppKit，无第三方依赖。应用不显示 Dock 图标。无需录屏权限，不采集屏幕图像；菜单使用应用图标与名称辨认项目，不复制原菜单栏图标的像素。

1.0.2 加入三角箭头应用图标，菜单栏使用无边框的原生箭头。展开列表仅显示应用名，省去系统输入法及扫描状态文字。需要排查时可选择「诊断…」。按住 ⌘ 可将入口拖到输入法左侧，macOS 会决定图标在空间不足时是否可见。

## 1.0.1 修复内容

此版本针对「辅助功能开关已打开但清单为空」及「后启动的应用未出现在清单」加强发现和重试：保留每个进程的实际辅助功能返回结果，对应用启动后尚未创建好的菜单栏项目继续扫描，并提供原生诊断窗口与重新启动入口。诊断会显示当前运行副本的路径、版本、PID 和实际 AX 返回，便于区分旧副本、授权身份与目标应用本身的问题。辅助功能设置中的开关状态不能代替实际读取结果。

## 安装和第一次使用

1. 解压 `TrayBridge-1.0.2-macOS15-Universal.zip`，把 `TrayBridge.app` 拖到「应用程序」文件夹，再双击打开。Apple 芯片和 Intel Mac 共用同一份应用。
2. 按应用的引导，打开「系统设置 → 隐私与安全性 → 辅助功能」，为「托盘展开 / TrayBridge」打开权限。只有获得此权限，应用才能读取和操作其他应用的菜单栏项目。
3. 点击菜单栏里的展开图标，再选择目标应用。若图标本身也被遮挡，用 **⌃⌥空格**打开菜单。
4. 如需开机后使用，可在菜单中启用「登录时启动」。移除应用前请先关闭这一选项并退出。

菜单支持键盘方向键和回车，也支持系统原生菜单的按名称定位。项目清单会重新扫描，以反映应用启动、退出和菜单栏项目变化。

选择列表中的应用即可打开对应项目的原菜单或面板。同一应用有多个项目时，可悬停查看项目名称和序号。按住 Option 选择可请求右键菜单，但需要目标应用支持。已有项目的菜单打开期间保持顺序稳定，后台刷新结果在下次打开时应用。

## 实现方式与兼容边界

应用通过 macOS 的 `AXExtrasMenuBar` 获取各应用实际注册的菜单栏项目，再请求该项目的 `AXPress` 动作。对支持辅助功能动作的应用，项目被刘海遮挡时也可以触发。它不是仅把图标在原菜单栏上展开，所以不依赖刘海两侧剩余的显示空间。

部分应用（尤其部分 Electron 应用）未正确实现这些辅助功能动作。系统返回失败时，工具会提示；此类应用的菜单无法保证打开。若应用返回成功但没有显示界面，工具也不能据此验证其内部行为。请以目标应用实际弹出的菜单为准。此版本不通过模拟鼠标拖动改变菜单栏布局。

工具需要目标应用仍在运行且确实存在菜单栏项目。它不能恢复目标应用自己移除的图标，也不会绕过锁屏或系统安全限制。系统固定项目与普通应用的可访问性结构可能不同。

## 本地签名说明

此交付物使用 **ad-hoc 本地签名**，没有 Apple Developer ID 签名或 Apple 公证。若 macOS 阻止首次打开，可在确认来源后前往「系统设置 → 隐私与安全性」选择「仍要打开」。不需要关闭 Gatekeeper 或系统完整性保护。

重新编译后签名会变化，辅助功能权限可能需要重新授权。若已打开权限却读不到项目，或正在从 1.0.0 升级，请依次处理：

1. 在旧副本的菜单中退出「托盘展开」。如有多个副本，先通过诊断窗口的运行路径和 PID 确认并退出旧副本。
2. 将新版 `TrayBridge.app` 安装到固定的「应用程序」位置，再从这个位置打开。不要直接覆盖仍在运行的旧应用。
3. 打开「系统设置 → 隐私与安全性 → 辅助功能」，仅移除旧的 TrayBridge 条目，再使用「+」添加刚安装的新版 `.app`，打开它的权限。
4. 从应用菜单重新启动，或退出后从同一安装位置再打开。用原生诊断窗口确认运行的是 **1.0.2（build 3）**、路径正确，并检查实际 AX 返回结果。

这一流程只重新授权 TrayBridge；不需要重置其他应用的权限，也不需要更改 Gatekeeper、系统完整性保护或其他安全设置。日常请通过 `.app` 启动，直接运行内部可执行文件可能使用不同的权限身份。若目标应用返回不支持辅助功能动作，重新授权不能使其获得该能力。

## 从源码构建

需要 macOS 15，以及 Apple Command Line Tools（包含 Swift 编译器和 macOS SDK）；无需完整 Xcode，无需下载依赖。首次编译前可以用 `xcode-select --install` 安装系统开发工具。

```sh
make build       # 构建 outputs/TrayBridge-1.0.2/TrayBridge.app，包含 arm64 和 x86_64
make test        # 运行无 UI 自检
make run         # 构建并打开应用
make package     # 构建并生成应用 zip、源码 zip、使用说明
```

`work/` 存放编译缓存和临时产物，`outputs/` 存放交付物。版本由 `Resources/Info.plist` 统一提供，构建输出放入版本目录，不覆盖旧版 `outputs/TrayBridge.app`。若当前版本输出仍被运行中的进程使用，脚本会拒绝覆盖，请先退出该副本；若无法完成进程检查，也会保留现有应用并输出检查记录路径。`make clean` 只清理临时构建和打包目录。

应用菜单中的原生诊断窗口可查看实际运行的路径、版本、PID 和 AX 扫描结果，优先使用它排查安装后的权限问题。`--diagnose` 为只读命令行入口；其权限状态取决于启动它的进程身份，不能代替安装后的权限验证。诊断不会为工具自动授予系统权限。

## 功能验证

无 UI 自检检查项目分类和动作重试规则，并运行独立的菜单栏几何与发现状态测试；编译和签名检查可检查交付物结构。核心的跨应用点击功能仍需安装后授予辅助功能权限，在实际 Mac 上验证：让一个支持辅助功能的菜单栏项目被刘海遮挡，打开托盘展开菜单，选择该项，确认出现目标应用的原菜单或面板。不同应用需分别验证，不能仅凭编译通过认定全部兼容。

自动测试包含 8 项核心检查、27 项几何检查和 16 项发现状态检查。以当前构建运行 `make test` 的输出为准。

1.0.2 已通过 macOS 15.8.2 上的双架构编译、签名验证及 51 项自动检查。新版跨应用点击、刘海遮挡与登录启动仍待实测。`Tests/ManualChecks.md` 提供桌面验收步骤，`Scripts/build-fixture.sh` 可构建独立测试宿主。
